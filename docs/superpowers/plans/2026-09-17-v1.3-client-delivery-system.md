# AZnet Theme v1.3 Client Delivery System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver AZnet Theme v1.3 as a WordPress-native Client Delivery System that produces professional inner Pages, reusable Page kits, a finished Footer system, a generic professional-services starter blueprint, and exact-package end-to-end delivery evidence without taking ownership of WordPress or provider domain data.

**Architecture:** Extend the existing hybrid PHP + `theme.json` architecture with focused Theme-owned presentation modules. Y1 adds a shared native Page renderer and bounded Page templates; Y2 adds portable Page-kit patterns; Y3 extends the existing single `aznet_theme_settings` schema with Footer presentation; Y4 extends the existing confirmed provisioning engine with a generic professional-services blueprint; Y5 proves the whole zero-plugin delivery journey and handles the separate final-candidate/version gate. Existing provider adapters remain unchanged and optional.

**Tech Stack:** WordPress 6.9+, PHP 8.1+, classic PHP theme templates, `theme.json`, native WordPress patterns/menus/Page Templates/Theme Mods, CSS, Node 22 + Playwright + axe for browser QA, GitHub Actions, deterministic Python release package builder.

**Spec:** `docs/superpowers/specs/2026-09-17-v1.3-client-delivery-system-design.md`

## Global Constraints

- Canonical repo: `truongdinhnamaz/aznet-theme`.
- Product scope: AZnet Theme only; do not code RootProfile, ConvertFlow, WooCommerce or another product.
- Governing rule: **SOURCE OWNS DATA. THEME OWNS PRESENTATION. INTEGRATION CONTRACTS CONNECT THEM.**
- WordPress owns Page/Post/Menu/Media/query state and lifecycle.
- WordPress + Theme alone must remain a complete Standalone Core path.
- Theme runtime floor remains WordPress `6.9+` and PHP `8.1+`.
- Theme architecture remains hybrid PHP + `theme.json`.
- Keep the single Theme-owned settings store `aznet_theme_settings`; no second settings store.
- No private provider API/storage reads, authoritative slug/title/Page-ID/URL heuristics, or copied domain stores.
- Native Posts/Pages retain the accepted Classic Editor policy; v1.3 must not silently re-enable Gutenberg for those post types. Pattern output is portable WordPress block markup and must remain editable/preservable through the accepted editor path.
- Theme metadata remains exactly `1.2.0` through Y1-Y4. Promotion to `1.3.0` is a separate Y5 owner gate after fresh final-candidate evidence.
- Production feature work uses RED -> intended failure -> minimal GREEN -> retained regression.
- Do not infer L3/L4/L6 PASS from L1/L2 evidence.
- Publication and production deployment remain separate approval gates after technical integration.
- Provider L5 is not part of v1.3 Core completion.
- Precondition for Task 1: the v1.3 source-ratification PR containing D-029/Y1-Y5 must be merged to canonical `main`.

```php
namespace AZnet\Theme;

function page_breadcrumbs_enabled(): bool {
    return true === setting('page_breadcrumbs', true);
}

function page_variant(?int $post_id = null): string {
    $post_id = $post_id ?: (int) get_queried_object_id();
    $template = $post_id > 0 ? (string) get_page_template_slug($post_id) : '';
    return match ($template) {
        'page-templates/wide.php' => 'wide',
        'page-templates/landing.php' => 'landing',
        default => 'standard',
    };
}

function page_breadcrumb_items(?int $post_id = null): array {
    if (!page_breadcrumbs_enabled()) { return []; }
    $post_id = $post_id ?: (int) get_queried_object_id();
    if ($post_id <= 0) { return []; }
    $ancestors = array_reverse(array_map('intval', get_post_ancestors($post_id)));
    $items = [];
    foreach ($ancestors as $ancestor_id) {
        $ancestor = get_post($ancestor_id);
        if (!$ancestor instanceof \WP_Post || 'page' !== $ancestor->post_type) { continue; }
        $url = get_permalink($ancestor_id);
        $title = trim((string) get_the_title($ancestor_id));
        if (!is_string($url) || '' === $url || '' === $title) { continue; }
        $items[] = ['title' => $title, 'url' => $url];
    }
    return $items;
}
```

Require the module from `inc/theme/bootstrap.php` after settings and before template-facing modules.
